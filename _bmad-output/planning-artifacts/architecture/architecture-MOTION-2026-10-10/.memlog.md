- (decision) Backend of record: existing Supabase project (venujhemegflfiszhtec) and schema, extended additively (new challenges/challenge_members/challenge_invites tables), not rewritten. Prevents: a parallel backend or destructive schema rewrite that discards the working pairing/WHOOP/auth system already in production.
- (decision) Habit matching is exact: a challenge defines ONE habit definition (title, category, period, kind, target, unit) shared by every member; joining clones that definition into the member's own habits row. User confirmed: 'everyone should have the same habits in the group.' Binds: leaderboard ranks raw progress value directly, no per-member normalization/ratio math needed.
- (decision) iOS client talks to Supabase DIRECTLY via the official supabase-swift SDK (auth + Postgres queries, RLS enforced identically to the web client) rather than proxying through the Next.js API. The Next.js API is retained ONLY for the operations that require server-side secrets: WHOOP OAuth code exchange, WHOOP webhook receipt, cron-driven WHOOP sync. Prevents: building and maintaining a duplicate 'mobile API' layer that could drift from Supabase's own RLS-enforced contract.
- (decision) Two integration sync mechanisms, by necessity not choice: WHOOP is server-pulled (webhook + cron hitting WHOOP's API with service-role credentials, as already built) because WHOOP exposes a real server API. HealthKit is device-pushed (the iOS app reads HealthKit locally via the HealthKit framework and writes entries to Supabase itself, authenticated as the user) because Apple provides no server-side/remote access to HealthKit data at all. Prevents: a future builder attempting a server-side HealthKit poller, which is not possible.
- (decision) HealthKit sync combines best-effort background delivery (HKObserverQuery + enableBackgroundDelivery) as a latency optimization with a GUARANTEED foreground sync on app launch/foreground as the real backstop. Web research (Oct 2026) confirms background delivery reliability is inconsistent in 2026 - some devices throttle to ~hourly, watchOS 26 has reports of delivery silently stopping until the watch restarts. Prevents: relying on background delivery alone and shipping a leaderboard that silently goes stale on some devices.
- (decision) Leaderboard ranking is computed server-side (a Postgres view/function joining challenge_members -> habits -> entries, reusing the existing period-bounds/progress logic already proven in lib/domain.ts, ported to SQL), not computed independently in the Swift client. Prevents: the existing TypeScript progress() logic and a future Swift reimplementation diverging on period-boundary or manual-vs-imported-precedence edge cases.
- (version) supabase-swift SDK v2.50+ (July 2026) verified via web search. Minimum requirements: Swift 6.1+, Xcode 16.3+, iOS 16 / watchOS 9. Binds: iOS client targets iOS 16+ as the deployment minimum.
- (constraint) Dev machine currently has only Xcode Command Line Tools (no full Xcode) - user is installing full Xcode from the App Store before any Swift code can be built/verified.
- (decision) iOS deployment target: iOS 17+ (overriding supabase-swift's stated floor of iOS 16) to use the modern @Observable macro for view state instead of legacy ObservableObject/Combine. By Oct 2026 iOS 17+ adoption is near-universal for a friend-group pilot audience. Prevents: screens built against two different state-observation patterns.
- (decision) Single Xcode app target, no SPM module split, for v1. 2-person team, one-week MVP timeline. Prevents: premature modularization overhead before there's a second consumer of any shared code.
- (direction) Deferred (carried from product brief, not re-decided here): Android client, web parity, screen-time integration (Apple API provides no viable cross-user export path), monetization. WhatsApp share uses the native UIActivityViewController share sheet - standard, no custom integration needed.

TestFlight internal testing is the obvious fit (up to 100 testers, no App Review wait on that track) but requires an Apple Developer Program account (99 USD/year) to be enrolled before any distribution beyond devices wired directly to Xcode.
